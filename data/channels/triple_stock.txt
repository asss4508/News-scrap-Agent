• HBM의 핵심 병목 현상은 ‘용량이 충분한가’에서 ‘1달러에 얼마나 많은 대역폭을 살 수 있는가’로 전환

**英伟达Rubin Ultra缩水，SemiAnalysis：瓶颈在于每单位带宽成本，而非每单位容量成本**
SemiAnalysis表示，英伟达 将 Rubin Ultra 的 HBM 从 12-Hi 下调至 8-Hi，核心原因并非单纯降低容量，而是当前 AI 推理真正受限的是 每单位带宽成本（$/bandwidth），而非每单位容量成本（$/capacity）。
HBM 堆叠层数主要决定容量，而总带宽更多取决于 HBM 堆栈数量、接口宽度和传输速率。因此，从 12-Hi 降至 8-Hi，可以减少约 1⁄3 的 DRAM 裸片用量，缓解当前紧张且昂贵的 HBM 供应压力，同时在堆栈数量和接口配置不变的情况下，仍可维持甚至提高整体带宽。
这意味着 英伟达 正在主动用更少的 HBM 容量换取更高的带宽经济性。对于越来越以推理为主的 AI 工作负载而言，模型并不只是需要“装下更多数据”，更需要持续、快速地搬运模型权重和 KV Cache，因此内存带宽的重要性正在上升。
Rubin Ultra 的调整反映出 HBM 竞争逻辑正在发生变化：AI 芯片追求的已经不再是单纯堆高 HBM 容量，而是在有限的 DRAM、功耗和成本约束下，获得尽可能高的有效带宽。HBM 的核心瓶颈正在从“容量够不够”，转向“每一美元能买到多少带宽”。

[2026-09-06 13:54] **●Rubin Ultra HBM 축소. 다음 병목은 CPU와 광인터커넥트로 이동**

• Rubin Ultra의 HBM 축소가 의미하는 것은 단순히 메모리를 덜 쓰겠다는 것이 아님. **AI 시스템의 최적화 기준이 ‘얼마나 많이 저장하는가’에서 ‘얼마나 빠르고 싸게 데이터를 이동시키는가’로 이동**하고 있다는 의미.

• 이 변화는 CPU에도 중요. GPU HBM이 모든 데이터를 품는 구조에서 벗어날수록 **HBM -> CPU Memory -> Context Memory/Storage**로 이어지는 메모리 계층 구조가 중요해짐.

• NVIDIA Vera CPU가 최대 **1.5TB LPDDR5X, 1.2TB/s 메모리 대역폭**, GPU와 **1.8TB/s NVLink-C2C**를 제공하는 이유도 여기에 있음. CPU의 역할이 단순 연산보다 **KV Cache 관리·데이터 이동·GPU 오케스트레이션**으로 확대.

• 따라서 CPU 경쟁의 기준 역시 코어 수만이 아님. 앞으로는 **Memory Bandwidth + CXL/NVLink + Coherency + I/O**가 AI CPU의 핵심 경쟁력. ‘GPU를 얼마나 잘 먹여 살릴 수 있는 CPU인가’가 중요해짐.

• 다만 HBM 용량 축소가 곧바로 CPU 출하량 증가를 의미하는 것은 아님. 직접적인 수혜는 CPU 연산 자체보다 **고대역폭 CPU Memory, SOCAMM, CXL, DPU, Context Storage** 쪽에서 더 크게 나타날 가능성.


**●더 직접적인 변화는 광인터커넥트**

• GPU당 HBM 용량을 줄이면서 모델과 KV Cache의 크기는 계속 커진다면, 부족한 용량은 결국 **더 많은 GPU와 더 큰 Scale-up Domain**으로 해결해야 함.

• 즉 개별 GPU 안의 HBM을 무한히 늘리는 대신, 여러 GPU와 랙에 흩어진 메모리와 연산 자원을 **초고속 네트워크로 하나의 시스템처럼 묶는 방향**으로 이동.

• 여기서 병목은 자연스럽게 HBM에서 **NVLink·Scale-up Network·Optical Interconnect**로 이동. 메모리 대역폭이 빨라질수록 GPU 사이의 데이터 이동 속도 역시 같은 수준으로 올라와야 GPU가 쉬지 않음.

• SemiAnalysis 역시 Rubin Ultra **NVL576처럼 Scale-up 영역이 여러 랙으로 확대되면 구리만으로 연결하기 어려워 광인터커넥트가 필요**하다고 분석. 향후 Scale-up 영역에서도 CPO/NPO와 광 연결의 역할이 커질 가능성.

• 결국 HBM에서 일어나고 있는 변화가 광통신에서도 반복될 수 있음. 중요한 것은 단순 포트 숫자가 아니라 **$****/Bandwidth****, pJ/bit, Latency**. 얼마나 적은 전력과 비용으로 더 많은 데이터를 이동시키느냐의 경쟁.

• AI 인프라의 병목은 사라지는 것이 아니라 **이동**함. GPU 연산 -> HBM 용량 -> HBM 대역폭으로 이동했다면, 그 다음은 **GPU와 GPU, 랙과 랙 사이의 대역폭**
**HBM을 덜 쓰게 됐다는 것은 광인터커넥트에 악재가 아니라 오히려 반대일 수 있음.
